## Pass B — completed

Two new tokens added to `index.css`, beyond the four from Pass A:
- `--status-progress-solid: #8b5cf6` — the solid "In Progress" purple used on white-text badges (booking status badges, technician job-status badges). Kept separate from the existing pastel `--status-progress-bg/-txt` pair, which is a different indigo meant for tinted pills.
- `--payment-cancelled-bg/-txt` (`#e2e8f0`/`#475569`, gray) and `--payment-refunded-bg/-txt` (`#cffafe`/`#0e7490`, teal) — payment-vocabulary-only concepts with no booking-status equivalent.

**Design decision — payment "Cancelled" stays gray, not red:** kept deliberately distinct from booking-status "Cancelled" (red). Reasoning: a cancelled bill is settled bookkeeping — there's nothing left to act on, and it isn't warning anyone about a mistake. Booking-status "Cancelled" is a "this didn't happen" signal that's worth flagging in a booking-status glance. The "something's actually wrong" case in the payment vocabulary is already covered by "Rejected" (still red) — the customer's proof-of-payment was refused and needs resubmission, which genuinely does need attention the way a red status implies. So: red is reserved for "needs action / went wrong," gray for "settled, no action, nothing wrong."

**Convergence direction for the rest of the payment vocabulary**: `billings.jsx` and `admin.css`'s `.status-pill--*` were disagreeing on two colors — "To Verify" was blue in `billings.jsx` but amber in `admin.css`; "Partially Paid" was the reverse (amber in `billings.jsx`, blue in `admin.css`). I converged `billings.jsx` to match `admin.css`'s existing choices rather than the other way, since admin's mapping was already the more semantically consistent one: "To Verify" is an awaiting-admin-action state (same category as booking-status "Pending," which is already amber app-wide), and "Partially Paid" is closer to an in-progress/informational state (blue). Both files now read `var(--warning)`/`var(--primary)` respectively instead of hardcoding either color.

**Files touched**: `index.css` (2 new token pairs), `admin.css` (`.status-pill--partial/-rejected/-refunded/-cancelled` now fully tokenized), `staff.css` (`.tech-status-in-progress` → `var(--status-progress-solid)`), `src/utils/statusColors.js` (`'In Progress'` now references the token instead of a bare hex), `customer/my_bookings.jsx` (deleted its local `getStatusColor`, now imports the shared one from Pass A — this also fixes a pre-existing bug where Pending and In Progress rendered identically, since the old local copy had no distinct `Pending` case), `customer/billings.jsx` (`getStatusColor` rewritten to return token references instead of hardcoded hex, per the mapping above).

Left untouched, deliberately out of this pass's named scope: the calendar's own confirmed/pending/completed/cancelled legend in `components/calendar.css` — it's internally consistent already and wasn't named in your list, but it does use yet another blue (`#3b82f6`) and green (`#10b981`) not tied to any shared token. Worth a look in Pass E if you want full closure.

## Pass C — completed

**`.modal-overlay`/`.modal-card`/`.modal-header`/`.modal-title`/`.modal-close-btn`**: `modals/payment_modal.css`'s versions are now the one canonical definition (circular icon close button, darker/blurred overlay, 16px radius/520px width) — this is also what was already rendering everywhere in practice, since that file loaded after `customer.css` and was winning. `customer.css`'s competing copies were deleted. One thing had to be ported over, not just dropped: `customer.css`'s `.modal-card` was `display:flex; flex-direction:column; gap:14px`, and several simple modals (`payment_modal.jsx`, `feedback_modal.jsx`, `back_job_modal.jsx`, the delete-account/reschedule confirm dialogs) depend on that gap for spacing between stacked elements with no margins of their own — dropping it would have collapsed all their content together with zero spacing. Merged into the canonical `.modal-card` in `payment_modal.css`. The admin review modals (`payment-review-modal`, used by `admin/payments.jsx` and `admin/back_jobs.jsx`) already give each of their own sections precise hand-tuned margins (4px/12px/16px/20px) and would have gotten a redundant extra 14px stacked on top of every one of them, so that modifier class gets `gap: 0` to cancel it back out. Small bonus: `.tech-job-modal` (staff modals) already had its own `gap: 10px` override, written assuming `.modal-card` was flex — it wasn't (payment_modal.css's version never was), so that gap was silently doing nothing before this fix and now actually works.

**Close button unified**: circular icon `.modal-close-btn` is now the one style, used everywhere, including retrofitted onto `.svc-modal`/`.ann-modal` (`service_manage.jsx`/`announcements.jsx`), which previously only had a text "Cancel" button. Also added `onClick={closeModal}` to both modals' overlay div and `stopPropagation()` on the inner card — they didn't close on backdrop click before, unlike every other modal in the app; small extra I made since "same modal language" seemed to clearly include that.

**`.sdm-overlay`/`.sdm-modal`**: worth flagging — `.sdm-close` turned out to be dead CSS, never actually referenced in either `admin_service_details_modal.jsx` or `user_details_modal.jsx`. So this wasn't really "a third separate close-button style" being used, it was no close-icon-button at all (same gap as `.svc-modal`/`.ann-modal` had, just not what the audit assumed). Fixed by adding a real button using the shared `.modal-close-btn` class, plus a small `.sdm-close-position` helper (`position:absolute; top:18px; right:20px`) since this modal's title lives in `.sdm-titlebar` alongside a status badge, not a `.modal-header` flex row the button could just drop into. Had to add `padding-right: 40px` to `.sdm-titlebar` so the badge doesn't sit underneath the new button — I couldn't visually verify this in a browser, worth a quick look.

**Dead classes removed**: `receipt-modal-overlay` and `receipt-modal-header` stripped from `receipt_modal.jsx` (both had zero CSS rules); `report-pdf-modal-overlay` stripped from `service_report_pdf_modal.jsx` (`report-pdf-modal-header` was kept — that one turned out to be real, it right-aligns the close button in a header with no title).

**`.receipt-modal-card` duplicate**: kept `modals/receipt_modal.css`'s version (480px/16px, already winning). One thing ported over rather than dropped: `customer.css`'s copy had `max-height: 85vh; overflow-y: auto` for scrolling a long receipt, which the winning version didn't have — merged that in so a receipt with several balance/proof rows can't overflow the viewport with no way to scroll.

**Primary buttons → `var(--primary)`**: `.svc-btn-primary`/`.ann-btn-primary`/`.svc-walkin-btn`/`.svc-add-btn`/`.ann-add-btn` dropped their `#4fc3f7→#1565c0` gradient for a flat fill (the gradient look is now reserved for the decorative menu-card pattern, not action buttons — see below). `.receipt-print-btn`/`.report-pdf-print-btn` had their own `#0f172a` override removed entirely, so they now inherit `var(--primary)` from `.modal-submit-btn` like every other button using that class. `.sdm-btn-primary` converged from `#0f172a` to `var(--primary)`. # Final summary — all 5 passes

Starting point: a UI consistency audit found 7 competing "primary blue" hex values, 3+ competing greens/reds/ambers, 5 independent status-color mappings that actively disagreed with each other (including two admin pages rendering the same status in different colors), 5 different modal chrome systems, 4 shapes for the same ghost/cancel button, 3 reds and 2 shapes for danger buttons, and inconsistent page titles/profile cards/hover shadows/hairline borders across the customer, staff, and admin portals.

**What changed:**
- **New design tokens, all in `index.css`**: `--primary`/`-hover`, `--success`/`-hover`, `--danger`/`-hover`, `--warning`/`-hover` (Pass A); `--status-progress-solid`, `--payment-cancelled-bg/-txt`, `--payment-refunded-bg/-txt` (Pass B); `--card-border`, `--card-hover-shadow` (Pass E) — on top of the pastel `--status-*-bg/-txt` pair that already existed but was itself only partially followed.
- **Real bugs fixed, not just style drift**: the `.bs-next-btn` cascade collision that made the primary booking-wizard button render green instead of blue; missing `tech-status-*` CSS that left three technician job statuses with no color at all; two admin pages silently disagreeing on "In Progress"'s color; swapped Approved/In-Progress colors in `.svc-badge-*`; a dead-but-actually-live `.status-badge` scheme in `customer.css` that was quietly overriding the correct one on `book_details.jsx`; `.sdm-close` and `.dashboard-welcome` both being referenced in JSX with zero CSS behind them; `manage_accounts.jsx` breaking when I deleted `.req-filter-pill` in Pass D without checking it had a second consumer (caught and fixed within the same session).
- **One consolidated status-color system** across booking statuses, payment statuses, technician job badges, and the admin calendar legend — five places that used to each maintain their own copy.
- **One modal language**: shared overlay/card/header/title/close-button, retrofitted onto the two modals (`.svc-modal`/`.ann-modal`) that had never had a close-icon button, and onto `.sdm-modal`, which turned out to have the same gap despite looking like it had its own close button.
- **One button system**: 10px radius for every action button (pill shape now reserved for filter/tab/tag controls only), one primary color, one ghost treatment, one danger treatment — replacing four independent primary-button looks, four ghost-button looks, and three danger-button looks.
- **One page-title class** (`.dashboard-welcome`) actually defined and applied everywhere, including 5 admin pages that had no title at all.
- **Converged profile cards, profile identity text colors, card hover shadows, and card hairline borders** between the customer and staff portals.
- **Deleted, not just tidied**: two entirely dead CSS families (`.ma-account-card`, `.svc-menu-card`) that no JSX anywhere referenced, plus the `.booking-filters`/`.req-filter-pill` dead weight left behind once their pages moved to shared classes.

**Judgment calls made along the way, all reported before moving to the next pass**: `#2563eb` as the one true primary blue (per your steer); payment-status "Cancelled" stays a deliberate neutral gray rather than red, and the calendar legend's cancelled state follows the same logic; ghost buttons converged onto `.bs-back-btn`'s look since it was already the most-used; danger buttons converged onto a solid fill rather than a light tint; `.sdm-btn`'s pill shape given up in favor of the 10px standard since modal size isn't a real reason for a different button shape; the admin queue-cards' own `#e2e8f0` hairline border left alone rather than force-matched to `--card-border`, since it was already internally consistent and the difference is barely visible.

**Not touched, flagged instead of silently decided**: the public marketing site's own `--navy`/`--navy-soft` button palette (a deliberate, separate brand system); the dead menu-card CSS's *content* (deleted the styling, didn't resurrect or remove the underlying unused components); the customer/staff pages beyond the admin portal that are still missing a page title (`billings.jsx`, `my_bookings.jsx`, both `profile.jsx`s, `book_details.jsx`, staff `reports.jsx`/`my_jobs.jsx`, both `calendar.jsx`s).

Every change across all 5 passes was verified compiling through the running Vite dev server as it was made.
